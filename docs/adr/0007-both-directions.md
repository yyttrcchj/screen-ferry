# 0007 两个方向都能控制

状态：已采纳

## 背景

到第 6 号决策为止，只有 Mac 能当服务端（捕获键鼠），只有 Windows 能当客户端（注入键鼠）：
Windows 的捕获和 Mac 的注入都是空的，角色按系统写死。键盘鼠标接在 Windows 上的人用不了，
两台 Mac、两台 Windows 之间也不行。

## 决定

### 角色

- 两个系统都能当服务端或客户端。缺省角色不变（Mac 当服务端、Windows 当客户端），旧配置照常工作。
- 角色在设置界面里改（`update_settings` 的 `role`）：后台断开现有的连接，以新角色重新开始，并写进 `config.toml`。
  `role` 字段原本就有，含义不变，不需要迁移。
- 命令行的 `serve`、`connect` 在两个系统上都能用。
- 本机信息新增 `platform`（本机系统），界面据此显示图标和按键名称。对方的系统不知道，按“和本机不一样”画。

### Command 与 Ctrl

- 互换只在两边键盘习惯不同（一台以 Command 为主、一台不是）时做：Mac 控制 Windows 时 ⌘ 当作 Ctrl，
  Windows 控制 Mac 时 Ctrl 当作 ⌘；Mac 与 Mac、Windows 与 Windows 之间原样发送。
- 握手能力新增 `COMMAND_KEY`（位 4），表示发送方以 Command 为主。服务端看客户端 `Hello` 里自己声明的这一位
  （不看交集），为每个会话分别决定。旧版客户端不声明它，而它们都是 Windows，行为不变。
- 引擎不能按系统写 `cfg`，“本机是否以 Command 为主”由应用经 `ServerConfig`、`ClientConfig` 传入。

### Windows 捕获

- 低级键鼠钩子（`WH_MOUSE_LL`、`WH_KEYBOARD_LL`）装在专用线程上，那个线程只跑消息循环。
- 钩子给出“这次移动之后光标会到哪”，此刻光标还在原处，两者之差就是位移，带着系统的指针速度和加速。
- 抓取时吞掉事件，光标停在主显示器中央并藏起来（复用客户端藏光标的透明窗口）。停在中央是为了四个方向都有余地。
- 光标在本机、贴着屏幕最外侧的边往外推时，系统已经把位置截在边上，位移为 0。连续两次推不动就补一个朝外的位移，
  让边缘切换照常判断。
- 按键先按虚拟键码认媒体键、Pause、Print Screen 和左右修饰键，其余按扫描码反查注入用的对照表，两个方向共用一张表。

### Mac 注入

- 从 HID 层发出 CGEvent，系统和程序都当成真实键鼠：按着鼠标键时发“拖动”，鼠标键带连击次数，
  按键带上此刻按着的修饰键，修饰键自己以“修饰键变化”发出，方向键、功能键带上真实键盘自带的标志。
- 音量、播放键以系统事件发出；Caps Lock 经 IOKit 直接改系统的锁定状态，按键事件改不了它。
- 关掉发事件之后对本机真实键鼠的 0.25 秒压制：被控制时本机的人也可能在用触控板。
- 光标在对方屏幕上时隐藏本机光标，本机的人一动鼠标就重新出现。
- 需要辅助功能权限，和当服务端时一样。

## 不做

- 同时当服务端和客户端（一台既控制别人又被别人控制）。

## 后果

- 键盘鼠标接在哪台上，哪台就当服务端；多台设备的布局（ADR 0006）以它为中心。
- Windows 常驻后台以管理员权限运行时，管理员权限的窗口在前台也能收到键鼠。UAC 的安全桌面和
  `Ctrl+Alt+Del` 仍不能远程操作；用 `serve`、`connect` 调试时，如果没有从管理员终端启动，管理员窗口仍会拦住输入。
- Windows 第一次监听端口时，防火墙可能询问是否允许 ScreenFerry 接受连接，需要允许。
